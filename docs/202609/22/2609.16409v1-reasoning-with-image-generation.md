## 摘要
思维链推理通过使大型语言模型（LLM）能够在回答之前将问题分解为中间步骤，彻底改变了自然语言处理。然而，将推理局限于文本领域，对于需要直接操作视觉表示的任务存在局限。近期研究通过外部视觉专家工具（如深度估计或目标检测模块）增强多模态 LLM，但这些工具由于依赖狭窄、僵化的操作，无法灵活生成或变换视觉内容，因而仍受根本限制。我们提出 ReImaGin，它利用图像生成模型作为多模态 LLM 的灵活视觉推理机制：与固定功能工具不同，它们接受自然语言命令，并能执行开放式视觉操作，例如移除遮挡，或根据房间多个不连续视角生成平面图。在包括多视图空间推理和碰撞预测在内的六项多样化视觉推理任务中，ReImaGin 始终优于纯文本推理和专业视觉工具基线，增益最高达 25%，展示了灵活、生成式视觉推理的优势。

## Abstract
Chain-of-thought reasoning has revolutionized natural language processing by enabling large language models (LLMs) to decompose problems into intermediate steps before answering. Yet confining reasoning to the textual domain presents limitations for tasks requiring direct manipulation of visual representations. Recent efforts augment multimodal LLMs with external visual expert tools such as depth estimation or object detection modules, but these remain fundamentally limited by their reliance on narrow, rigid operations that cannot flexibly generate or transform visual content. We propose ReImaGin, which leverages image generation models as a flexible visual reasoning mechanism for multimodal LLMs: unlike fixed-function tools, they accept natural language commands and can perform open-ended visual operations, like removing an occlusion or generating a floorplan from multiple disjoint views of a room. Across six diverse visual reasoning tasks including multi-view spatial reasoning and collision prediction, ReImaGin consistently outperforms both text-only reasoning and specialist vision-tool baselines, with gains of up to 25\%, demonstrating the advantage of flexible, generative visual reasoning.

## 1. 核心问题与整体含义

- **研究背景**：思维链（CoT）推理让 LLM 在回答前生成中间推理步骤，极大提升了 NLP 任务表现，并扩展到多模态领域（VQA 等）。但绝大多数多模态框架仍把"推理"限制在文本域——用语言描述视觉输入再做逻辑处理。
- **核心问题**：文本中心的推理方式不适合需要空间或物理直觉的任务（例如想象移除遮挡后的样子、合成新视角、绘制碰撞轨迹）。近期工作尝试为多模态 LLM 接入外部视觉专家工具（裁剪、深度估计、目标检测、分割），但存在两个根本局限：
  - **工具僵化**：只能执行预先实现的窄操作，无法灵活生成或执行复杂变换（如想象一个替代视角）。
  - **依赖手工示例**：通常靠人工编写的 in-context 示例教模型使用工具，增加人工成本并限制对新任务的泛化。
- **整体含义/主张**：图像生成模型本身可以作为**灵活的视觉推理机制**——它接受自然语言指令，可执行开放式视觉操作（去遮挡、由多视角生成平面图、画轨迹线等），一个生成模型即可整合多种专家工具能力，且其能力随生成模型进步而自然扩展。

## 2. 方法论

### 核心思想
- 提出 **ReImaGin**：一个多模态 agent，在迭代推理循环中**交错文本思维链与图像生成模型调用**，把生成的图像作为**中间推理状态**（而非最终产物）。
- 与固定功能工具不同，核心工具 `generate_image` 是自由形式的：接受任意自然语言提示（可选参考图），返回合成图像并注入 agent 上下文。

### 关键技术细节
- **Agent 架构**（基于 ReAct）：
  - 每轮上下文 $C_t = (Q, V, h_1, \dots, h_{t-1})$，其中 $h_i = (\theta_i, \alpha_i, o_i)$ 分别为第 $i$ 轮的思维链理由、可执行动作、动作输出。
  - **推理步**：MLLM 基于 $C_t$ 产生 CoT 理由 $\theta_t$。
  - **动作步**：产出 Python 程序 $\alpha_t$ 并运行时执行，可调用 `generate_image`、程序化图像工具（crop、overlay、subtract、numpy 等）及通用代码。
  - **上下文更新与终止**：动作输出（含生成图像）作为新用户消息追加；当理由中出现 `TERMINATE` 时结束并从文本中解析答案。
- **Prompt 组成**：工具描述 + in-context 示例（演示视觉推理策略）+ 当前上下文。
- **图像生成的测试时缩放（Test-Time Scaling）**：
  - 图像生成是随机的，难度越高方差越大（如生成平面图）。
  - 做法：`generate_image` 独立采样 $N$ 个候选，再用一个 MLLM 选择器挑选最忠实于提示的一张（对 agent 接口不变，始终只收到一张图）。
  - 与以往"采样多条文本 CoT 再投票"不同，这里只采样**一条推理轨迹**，把额外算力花在改进生成图像上。仅在 MMSI 任务上启用（$N=10$）。
- **自动发现视觉推理策略**：
  - 将"策略发现"化归为 **prompt 优化**：给定任务 $\tau$、训练集 $D_{train}$、开发集 $D_{dev}$，寻找能诱导有效工具使用的 prompt $p^*$。
  - 从 "No Strategy" 基线 prompt 开始；每轮交替两个阶段：
    - **候选评估**：用 $P_r$ 中每个 prompt 在训练/开发集上运行 agent，用真值算指标，识别成功与失败轨迹；开发集分数 $J(p)$ 用于选择。
    - **候选提案**：提案 agent $A_P$ 接收保留的 prompt 及训练集中的成功/失败轨迹，生成新 prompt。
  - 搜索中推理 agent 与图像生成器固定不变，**只优化 agent prompt**；提案阶段不涉及人工任务特定策略。
  - 实现用 Opik；设置 $R=4$ 轮、每轮 5 个候选、$|D_{train}|=|D_{dev}|=50$。

- **开源生成器**：在简单编辑类操作（裁剪、叠加、画线、局部擦除等）上，FLUX.2 [dev] 与 Qwen-Image-Edit-2511 的表现接近闭源生成器，任务准确率差距有限；但在依赖强世界知识或复杂几何合成的任务（如由多视角照片生成俯视平面图、想象被遮挡物体的完整形态）上明显落后，生成结果常出现结构不一致、视角混乱或物体身份漂移，进而拖累下游推理。结论是：ReImaGin 的性能**随生成模型能力单调受益**，方法本身不绑定特定生成器，但当前对生成质量有实质依赖。
- **自动发现的策略优于无策略基线**：在 5 个任务上，自动优化得到的 prompt 稳定超过 "No Strategy" 基线，并接近人工设计的任务特定策略；成功轨迹显示 agent 自发学会了"先重绘/去遮挡再计数""先合成中间视角再比较"等策略，而非被告知。这说明视觉推理策略可以像文本 CoT 提示一样被**自动搜索**，降低人工示例成本。
- **跨 MLLM 迁移有效**：把 Gemini 上发现的 prompt 原样迁移到 Qwen-3.5-27B，仍能带来相对 No Tools / Sketchpad 的提升，虽不及在 Qwen 上重新优化的版本，但表明发现的是**任务层面的通用策略**而非对特定模型的过拟合。
- **忠实度与正确率正相关**：人工审计的 120 张生成图中，被判为"忠实于提示"的图像对应更高的最终正确率，不忠实的图像（物体数量错误、空间关系颠倒、身份混淆）几乎总是导致错误答案。论文据此强调**图像中间状态的保真度是性能瓶颈**，这也是测试时缩放有效的原因。

## 7. 局限与失败模式

- **视觉幻觉会污染推理链**：生成模型可能在"想象"时篡改原图事实（凭空增加/删除物体、改变颜色或朝向），而 agent 往往信任生成结果继续推理，错误被放大而非纠正。这是交错式图像推理的固有风险，论文未提出显式校验机制。
- **专用工具在窄任务上仍不可替代**：深度推理任务中，Sketchpad 借助专用深度估计器（99.2%）反超 ReImaGin（94.6%），说明"通用生成"在需要度量精度（深度、尺寸、精确几何）的场景下不如标定过的专家模块，二者更可能是互补而非替代关系。
- **成本与延迟显著上升**：每实例费用从约 $0.04 升至 $0.16、中位时延从 52 s 升至 76 s，且自动策略发现需一次性约 $214/任务；对高吞吐或低延迟场景不友好。
- **随机性与方差**：生成过程随机，难度越高方差越大，必须靠采样+选择器（N=10）缓解，进一步抬高成本；论文也仅在 MMSI 上启用 TTS，其他任务因方差小而关闭，说明该收益并非普遍。
- **评测层面的弱点**：MIRA 仅 26 例、Path Tracing 为自建基准且无第三方验证、忠实度审计样本仅 120 张且论文自认是相关性而非因果、自动策略发现未覆盖全部任务。
- **未披露硬件与环境**：虽然方法 training-free，但完全依赖闭源 API，复现性受服务版本、接口稳定性影响。

## 8. 总体评价与启示

- **核心贡献**：把"图像生成"从任务终点重新定位为**推理过程中的中间状态**，并用 agent 循环把文本 CoT 与自由形式的视觉操作统一起来。相比固定工具箱，`generate_image` 以单一接口覆盖了去遮挡、视角合成、轨迹绘制等多种操作，且能力随生成模型进步而免费升级——这是与 Visual Sketchpad 一类工作的本质区别。
- **方法论亮点**：① 严格的内部消融（no-op 替换）把"生成能力"从 prompt/脚手架差异中干净地隔离出来，使因果归因可信；② 只在图像上做测试时缩放而非采样多条文本 CoT，是一种针对该范式特点的算力分配策略；③ 把策略发现形式化为 prompt 优化并自动化，减少人工示例依赖。
- **对领域的启示**：多模态推理的瓶颈可能正从"语言推理能力"转向"视觉想象的保真度"；未来值得探索的方向包括生成结果的自动校验/回溯机制、生成器与专家工具的混合路由、以及在度量精度任务上让专用模块与生成模块协同。方法对生成器质量敏感这一事实，也意味着它是一份"随基础模型进步而升值"的框架。
