## 摘要
视频中的开放词汇目标检索需要在有界查询时间成本下回答自由形式的物体查询。现有的基于索引的系统通常存储独立的帧级区域，并通过视觉-语言相似度进行检索；这对于外观查询有效，但与证据具有时间性或关系性的谓词不匹配，例如停止状态、场景区域占用、持续性和物体交互。我们将这一差距识别为证据单元不匹配：查询是在轨迹片段或物体元组上表达的，而索引存储的是孤立边界框。为解决该问题，我们提出 STEG-OVR，一种用于开放词汇目标检索的结构化时空证据图。STEG-OVR 将持久物体表示为轨迹片段节点，将时间上兼容的物体对表示为关系边，存储外观、运动、场景占用、相对几何、速度兼容性以及符号关系证据。查询被分解为实体、状态、场景、时间与关系槽位，这些槽位仅激活相应的检索通道，然后进行软分数融合和固定预算一致性验证。在三个以物体为中心的设置上的诊断实验显示，Beach 上的 AP 从 0.0882 提升到 0.2073，Shibuya 上从 0.0834 提升到 0.1505，在 LOVO 风格比较中从 0.701 提升到 0.743。对于停止状态和场景区域占用查询，增益最强，而持续关系仍对跟踪连续性和谓词校准敏感。

## Abstract
Open-vocabulary object retrieval in videos requires answering free-form object queries under bounded query-time cost. Existing index-based systems typically store independent frame-level regions and retrieve them with vision-language similarity, which is effective for appearance queries but mismatched with predicates whose evidence is temporal or relational, such as stopped state, scene-region occupancy, persistence, and object interactions. We identify this gap as an evidence-unit mismatch: the query is expressed over tracklets or object tuples, while the index stores isolated boxes. To address it, we propose STEG-OVR, a structured spatio-temporal evidence graph for open-vocabulary object retrieval. STEG-OVR represents persistent objects as tracklet nodes and temporally compatible object pairs as relation edges, storing appearance, motion, scene occupancy, relative geometry, velocity compatibility, and symbolic relation evidence. A query is decomposed into entity, state, scene, temporal, and relation slots, which activate only the corresponding retrieval channels before soft score fusion and fixed-budget consistency verification. Diagnostic experiments on three object-centric settings show AP improvements from 0.0882 to 0.2073 on Beach, from 0.0834 to 0.1505 on Shibuya, and from 0.701 to 0.743 in a LOVO-style comparison. The gains are strongest for stopped-state and scene-region-occupancy queries, while sustained relations remain sensitive to tracking continuity and predicate calibration.

# 论文总结：Structured Spatio-Temporal Evidence Graphs for Open-Vocabulary Object Retrieval in Videos

## 1. 核心问题与整体含义
- **研究背景**：视频开放词汇目标检索需要以有界在线成本回答自由文本查询。现有索引式系统通常离线抽取帧级区域嵌入，在线通过视觉-语言相似度检索。
- **核心问题**：这类系统对“红色汽车”“背背包的人”等外观查询有效，但对“停止的物体”“在人行横道中的物体”“两个并排物体”“一辆车跟随另一辆车”等查询失效。
- **关键概念**：作者将问题定义为**证据单元不匹配**——查询语义单元是轨迹片段或物体元组，而索引存储的是孤立帧级检测框。
- **整体含义**：不应在查询时临时做跟踪、关系推理或视频语言推理，否则会破坏索引式检索的效率优势；应让离线索引存储与查询谓词粒度一致的证据。

## 2. 方法论：STEG-OVR
- **核心思想**：构建结构化时空证据图，将持久物体表示为**轨迹节点**，将时序兼容物体对表示为**关系边**；查询被分解为结构化槽位，仅激活所需检索通道。
- **离线建图**：
  - 使用双采样率：关键帧约 1 fps 用于开放词汇外观嵌入，跟踪帧约 5 fps 用于时序连续性与运动估计。
  - 通过 IoU、中心位移、外观余弦距离构成关联成本，做二部匹配，将检测链接为轨迹片段。
  - 轨迹节点描述子包含外观、运动、轨迹、状态、场景证据。
  - 外观描述子为关键帧嵌入的置信度加权归一化平均。
  - 运动证据由归一化中心轨迹计算平均速度；停止状态用速度阈值与 sigmoid 得到软分数。
  - 场景证据用物体框与预定义区域掩码/多边形的交并比在轨迹时间上平均，得到软占位分数。
  - 关系边仅在轨迹时间重叠超过阈值时创建，存储相对中心位移、平均距离、速度对齐、时间 IoU 和符号关系标签，如 near、left-of、right-of、side-by-side、following。
- **索引布局**：混合索引包含外观 ANN 索引、运动/状态桶、场景区域桶、时序区间桶、关系标签列表及边描述子指针；轨迹回指针仅用于可视化和验证。
- **在线检索**：
  - 查询解析为实体、属性、运动/状态、关系、场景、时间槽位；未匹配词保留在外观短语中。
  - 用通道掩码控制激活哪些索引和分数项。
  - 单物体查询：外观 Top-K 与运动、场景、时间桶保守交集生成候选。
  - 关系查询：先分别生成实体候选，再通过预物化关系边连接，避免在线枚举所有物体对。
  - 分数融合：单轨迹分数为外观、运动、场景、时间等活跃证据项加权和；关系候选再加入边分数与两个节点分数。
  - 通道权重查询自适应，由掩码和先验控制。
  - 最后对 top-ranked 候选做固定预算一致性验证，最终分数为检索分数与一致性分数的加权组合。
- **成本语义**：单物体查询从轨迹节点检索，关系查询从预物化边检索；通常轨迹数远小于帧级检测数，且避免在线物体对枚举。

## 6. 主要结论与发现
- STEG-OVR 在三个物体中心设置中均提升 AP：
  - Beach：0.0882 → 0.2073。
  - Shibuya：0.0834 → 0.1505。
  - LOVO 风格比较：0.701 → 0.743。
- 增益最大的是**停止状态**和**场景/区域占位**查询，说明轨迹速度聚合和区域占用时间累积有效。
- 多物体邻近查询也有改善，关系边减少了独立检索物体的歧义。
- 持续关系和时序动作不是主要增益来源，对跟踪连续性和谓词校准敏感。
- 粗粒度相对区域查询，如 bottom、left/right、center-of-road，容易出现阈值过筛和边界跨越问题。
- 消融显示场景证据最重要，其次是运动证据和关系证据；物体中心基准上去查询分解、去运动、去场景均导致性能下降。
- 在线时间仅小幅增加，说明图索引在测量日志中没有显著抬高在线检索成本。

## 7. 优点
- **问题定义清晰**：明确提出“证据单元不匹配”，将帧级索引与轨迹/元组查询之间的矛盾形式化。
- **索引粒度对齐谓词**：外观保持开放词汇向量检索，状态、场景、时间、关系证据在离线物化到轨迹和轨迹对，符合谓词语义。
- **混合图索引设计**：向量检索与符号桶、关系边结合，兼顾开放词汇召回和结构化过滤。
- **通道选择性**：查询槽位和通道掩码避免对纯外观查询做无关关系推理，也避免关系查询退化为外观相似度。
- **可解释与可审计**：不同证据通道有直接检索含义，比单一跨模态分数更易分析。
- **兼容现有系统**：可复用开放词汇检测器、跟踪输出、ANN 索引，不替代底层视觉模型。
- **实验分析较细**：包含主结果、Top-K、查询族、消融、per-query 和效率分析，能定位增益与失败案例。
